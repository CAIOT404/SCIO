The recovery supervisor no longer reads a machine sleep as a hung build. Its hang check counts only time it observed: when two polls of a supervised run are more than 5 minutes apart, the machine was down, and the gap is recorded on the run (`downtime_s`, with a note) and left out of the idle time. A build with no progress for `hang_after_s` of awake time is still killed. While a build is alive, `recovery run` asks Windows not to sleep on its idle timer, and `python -m recovery status` shows a run's downtime. Before, a PC that slept 29 hours two seconds after a graphcalc build started had the build killed as a hang at the wake, with an issue (#158) and a repair session for a build that had done nothing wrong (I-240).
