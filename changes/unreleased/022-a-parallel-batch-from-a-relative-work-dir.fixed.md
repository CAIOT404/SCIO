A parallel batch run from the default relative work directory (`scio build` passes none) builds each feature in its own worktree again. The worktree path was relative, so git, which runs in the product tree, made the worktree inside the product. The feature's sandbox, resolved in the workspace, was an empty directory there, and its clone failed with "repository '.scio\worktrees\...' does not exist". The work directory and the worktree root are now absolute. A worktree whose stored path is stale is added again, and a worktree the bug left inside the product tree is removed before the next batch (issue #142, I-229).
