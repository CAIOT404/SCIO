`scripts/land.py` follows the owner's streamline plan (issue #141). A PR whose CI passed and that changes only docs or tests (`risk_of`: `docs/`, `changes/`, `tests/`, or Markdown outside the runtime, its prompts, the tools, hooks, evals, `.claude/` and `.github/`, never `CLAUDE.md`) gets its merge line with no approval, and the `low-risk` label. A `revert: #N` PR whose body says `Reverts #N` gets its merge line too, labelled `revert`, when #N is merged and the revert touches only #N's files. Any other PR still waits for the owner, and land.py names the paths that need the review. There is no update-branch step any more: the ruleset no longer requires an up-to-date branch, and a conflicting PR stops. `main` requires a merge queue, and the merge line is now `land.py N --enqueue`. It re-checks the same basis (never a high-risk PR without an approval) and CI on the head, then adds the PR to the queue with GraphQL's `enqueuePullRequest`, pinned to that head. A PR already queued is left as it is. Nothing prints `gh pr merge` any more: under the queue it goes through auto-merge, which this repository refuses (I-233). `--after-merge` waits while the PR is queued (`--queue-timeout`, 30 minutes by default). It then watches main's CI run for the merge commit (unless `--no-watch-main`). When that run fails, it opens a `red-main` issue with the run's URL, prints the revert recipe, and exits 1.
