The recovery supervisor never moves live-wt backwards. After a repair PR merges, a live-wt whose HEAD already contains the merge commit (the owner moved it to a newer `main` with `scripts/move_live_wt.py`) stays where it is, with a timeline note, and the health check, the `uv.lock` comparison and the resume run on that HEAD. A lock change made on `main` after the repair is no longer blamed on it. Before, releasing the held graphcalc incident (#142) would have moved live-wt from `main`'s tip back to the repair's merge commit (I-237).
