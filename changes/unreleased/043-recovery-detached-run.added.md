`python -m recovery run --detach` starts a supervised build that no session owns, and `python -m recovery wait --workspace W` waits for its stop ([docs/RECOVERY.md](docs/RECOVERY.md), issue #175). `run --detach` starts the same supervised run as a detached process, prints its run id and stdout path and returns at once; a busy workspace is refused as before (exit 2). `wait` blocks until the workspace's run ends, prints the tail of its stdout and exits with its exit code. It only reads the store, so it can be killed and started again without touching the build. Before, a build was a child of the session that started it: one died with its session and stayed down for 200 minutes, and another kept a background session open that the owner could not close (I-246). Without `--detach`, `run` is unchanged.
