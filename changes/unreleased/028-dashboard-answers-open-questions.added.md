The dashboard lists the parked features' design questions and answers them (ADR 0020 decision 6, issue #141 part 5). An "Open questions" section shows each one's feature, attempt, question, age and issue link, with an answer box; the count shows beside the other attention items. `POST /api/answer` is the dashboard's one write: it needs a token the app makes at each launch, which only the page it served carries. It posts an `answer:` comment on the feature's issue through `gh` (bounded at 30 s) when the build has a GitHub repository, and writes the workspace's answer file (`scio/product/questions.py`) in every case. So a failed post loses nothing, and the page says why it failed. It never writes a checkpoint.
