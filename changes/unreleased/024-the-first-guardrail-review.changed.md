The first guardrail review (issue #141): the 100 Always/Never rules are now 21 active rules, read in one place, `docs/guardrails/ACTIVE.md`. 75 rules are merged into an active rule that keeps each of their instructions as a clause and cites their ledger ids. 4 are retired, because a docs check, a test that pins the gate or an autouse fixture enforces them fully. A rule file may carry a status line, `Status: merged into <n>` or ``Status: retired: `<guard>` enforces it``; no number is reused and no rule file is deleted. `check_guardrails` checks the status lines: a merge target is active and cites the merged rule's ids, and a retired rule's guard exists and is not `manual:`. A ledger entry stays covered when an active or a retired rule cites it. `ACTIVE.md` names the review's cut-off (`Reviewed through rule 100 on 2026-11-15.`), and `check_active_guardrails` fails when it drifts from rules 1 to that cut-off; a rule added after the review needs no change there, so pull requests that add rules never conflict on it. `uv run python scripts/check_docs.py --active` prints every active rule, those added since the review included, and the recovery repair brief now reads the rules through it. `--write-active` writes `ACTIVE.md` at a review. `docs/guardrails/README.md` explains the status lines and the review.
