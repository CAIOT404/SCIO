A feature attempt that ends with a design question no longer stops the product build: the feature parks and the milestone's other features keep building, alone or in batches (ADR 0020, issue #141 part 5, I-235).
- With `--gh`, the question is commented on the feature's issue, and the issue gets the `needs-answer` label. Offline, it is added to the feature's issue file under `.scio/product/issues/`. Each question's id is its attempt's thread id (for example `build-graphcalc-m4-p29-a1`), so a later milestone's question is never mistaken for an earlier one's.
- An `answer:` comment on the issue, or the workspace's answer file `.scio/answers/<question id>.md` (what the dashboard writes), gives the feature its next attempt with the question and the answer in its task, as `retry: <answer>` does (#137). The build reads answers before every feature pass and before the gate. With GitHub, it takes the label off and comments that the answer was received.
- Only when nothing else in the milestone can build does the build stop, once, at `questions_wait`, listing every open question with its issue link. `proceed` defers the parked features as `skip` does, takes their labels off and says so on each issue. `stop` ends the build. Any other reply, or running `scio build` again, reads the answers again.
- A failed GitHub post never halts the build: the feature stays parked, the ledger says what failed, and the next pass tries again.
- A failure without a question still stops for `retry`, `skip` or stop.
