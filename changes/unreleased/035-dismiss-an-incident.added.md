`python -m recovery dismiss <incident> --reason "<text>"` ends an incident that was not a SCIO fault (issue #163). It moves an open incident, a held one included, to the new terminal state `dismissed`, and records the reason on its timeline, in its status comment and in one comment on its issue (a GitHub failure is a timeline note, never an error). It starts no repair and no replay and never touches live-wt. A dismissed incident is not open: `python -m recovery status` lists it under "dismissed by the owner, not open", the tick ignores it, and `scripts/move_live_wt.py` no longer waits on it. The command exits 1 and changes nothing for an incident that is already closed, escalated or dismissed, and while a tick is driving the incident (a running repair session: hold it, wait for the session to end, then dismiss). Before, a false alarm such as a machine sleep read as a hang (#158) could only be held, which kept live-wt from moving, or released, which started its repair again.
