### I-149 · A milestone planned a second time was retitled, so its GitHub milestone was duplicated
- Found: 2026-11-04 · issue #79, the graphcalc live run's S7 · thread `build-graphcalc-m2`, 18:50 UTC 2026-10-31
- Symptom: `--decision merged` on `build-graphcalc-m1` planned M2 and created GitHub milestone #2 "M2: Calculator errors, history, variables and UI" with issues #8 to #11. P5 attempt 1 was then killed, and the next plain `scio build` ran as a new thread (`build-graphcalc-m2`), which ran `milestone_planner` again; it retitled the milestone "...variables and **tab** UI", and `ensure_milestone` (`scio/harness/github/client.py:248`, matched by title) created milestone #3.
- Root cause: a milestone's plan lived only in the checkpoint of the thread that made it. A thread that stops inside a milestone (killed, crashed, halted at a feature, or `stop`) leaves the milestone planned but not recorded, so the next thread starts at `load` and asks the planner again; a model's title is not stable across calls, and the GitHub milestone was identified by its title. Picking the old thread in the CLI instead is no fix: graphcalc's `progress.json` still names `build-graphcalc-m1`, the thread abandoned mid-P5 (checked).
- Fix: `plan_milestone` commits the plan on the milestone branch (`.scio/product/milestones/Mn-plan.json`, `[scio:plan:Mn:plan_milestone]`) and, when it plans milestone n again, reuses the stored plan (`stored_plan`) while its features are still the first open features in PRODUCT.md order, the normaliser's rule (I-046): the same title, features and tiers, no planner call. A feature inserted ahead of them at a stop makes it plan again (found by the advisor's review); each distinct plan gets its own commit marker (`[scio:plan-<digest>:Mn:plan_milestone]`), so a plan made again is committed too. The `issues` node adopts a GitHub milestone that already carries the id (`find_milestone_by_prefix("Mn: ")`, I-150's helper) for a branch from before this fix. The shared tail of `plan_milestone` is `_start_milestone`.
- Sweep: every identity SCIO derives from model text on GitHub or in git (`grep -n "ensure_\|find_" scio/product/build.py`): milestones (fixed); issues are `Pk: description` from PRODUCT.md, not model text (stable; I-150 fixes their lookup); the PR is found by its head branch, the release by its tag; branch names come from the milestone number and `slug()` of the feature. ADR 0011 decision 4 amended.
- Guard: `test_a_milestone_planned_again_reuses_its_plan_github_milestone_and_issues` (a planner that retitles on every call; one call, one milestone, no new issue), `test_a_retitled_milestone_finds_its_github_milestone_by_its_id`, `test_a_stored_plan_is_not_reused_ahead_of_a_feature_inserted_before_it` (fails on a subset-only reuse rule: one planner call, P1 first); the first two fail on `fix/77-product-md-cap` (no plan file; a second milestone `M1: Milestone 1`); guardrail 49
- Resolved: 2026-11-04 · Status: resolved. graphcalc's leftovers (open issue #8, milestones #2 and #3) are the owner's to close.
