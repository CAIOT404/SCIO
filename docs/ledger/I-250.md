### I-250 · The worker's summary resume changed the tool list and wrote the whole context to the prompt cache again
- Found: 2026-11-18 · workflow audit 2026-11-17, item 4 (#185) · scio/loop/claude_code_worker.py, ClaudeCodeWorker._summary
- Symptom: every Claude Code worker session ends with a `--resume` call for the typed summary, and that call read nothing from the prompt cache. It wrote the whole session to the cache again. The audit's probe (`.scio/agents/audit-item4-cache.md`) measured the exact old argv at 0 tokens read and 12,790 written ($0.0533). A resume with the session's own flags read 33,431 and wrote 100. In graphcalc the summary writes were 44k to 97k tokens a session, about 15% of a feature's cost at API prices (on Max it is plan usage).
- Root cause: tool definitions are part of the cached prompt prefix: "the cache invalidates when the set of tool definitions in the request changes between turns" (https://code.claude.com/docs/en/prompt-caching). The summary passed `--tools ""`, which removes the built-in tools, and `--json-schema`, for which Claude Code adds a `StructuredOutput` tool. Its tool list differed from the session's, so every summary missed the cache. The flags were chosen to forbid edits and to get a typed answer (I-077). Nobody checked them against the cache.
- Fix: `summary_argv` resumes with the session's tool list: no `--tools`, no `--json-schema`, no `--allowedTools`, and `--permission-mode dontAsk --permission-prompts none`.
  - The schema travels at the end of the prompt (`summary_ask`, after `SUMMARY_SCHEMA_PROMPT`). `summary_reply_json` strips one code fence from `result` and parses it, and `validate_with_trimming` validates it. An invalid reply is asked again once, with the error, as before. `SUMMARY_MAX_TURNS` stays 3.
  - The mode is passed because the probe showed the design without it let an edit through. A `-p --resume` starts in the mode a new `-p` run would (https://code.claude.com/docs/en/sessions.md, "Permission mode on resume"): the settings' `permissions.defaultMode`, which is `auto` on the owner's machine. `dontAsk` "auto-denies every tool call that would otherwise prompt you"; reads inside the working directory still run (https://code.claude.com/docs/en/permission-modes.md).
  - Live probe, Claude Code 2.1.327, claude-sonnet-5, one session, from a new temporary directory. (a) A turn with `worker_argv`'s flags read one file. (b) The exact new argv and stdin, before `dontAsk` was added: 28,144 tokens read, 1,078 written, one turn, no tool call, and the reply parsed into `WorkerOutput`. (c) The same argv, told to Write a file first: the Write ran and the file was created. (d) The final argv with `dontAsk`, told the same: 62,698 read, 1,452 written, the Write denied (`permission_denials`), no file, and a valid reply on turn 3 of 3. $0.105 in all at API prices, nothing billed.
- Sweep: two constructs, each searched in `scio`, `recovery` and `scripts`.
  - A changed tool list on a resume: `grep -rn --include='*.py' -e '--resume' -e '--json-schema' -e '"--tools"' scio recovery scripts`.
    - The worker's tool resume (`resume_argv`) passes the session's own flags again, so it keeps the tool list.
    - `ClaudeCodeProvider` (`--tools "" --json-schema`) and the recovery repair (`recovery/repair.py`, `--json-schema`) each start a new session with one constant tool list, so they have no earlier cache to miss.
    - No other call resumes a session.
  - A `claude -p` run whose permission mode comes from the settings: `grep -rn --include='*.py' -e '"-p"' scio recovery scripts`, four builders.
    - The worker's turn and tool resume (`_tool_turn_argv`) pass `--permission-mode acceptEdits`.
    - The summary (`summary_argv`) now passes `dontAsk`.
    - The recovery repair passes `cfg.permission_mode`.
    - `ClaudeCodeProvider` passes `--restricted --tools ""`, so it has no tool for a mode to allow.
    - The fifth hit, `recovery/procs.py`, is `ps -p`.
- Guard: guardrail 128. `test:test_the_summary_resume_keeps_the_sessions_tool_list` and `test:test_the_summary_denies_tools_without_a_prompt`, in `tests/unit/test_summary_cache.py`.
