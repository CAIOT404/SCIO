### I-122 · Worker turns on the Claude Code backend emit no OpenTelemetry spans
- Found: 2026-10-27 · issue #68, wave 1 (agent D, writing `docs/OBSERVABILITY.md` from `scio/harness/telemetry.py`) · `ClaudeCodeWorker` (`scio/loop/claude_code_worker.py`) records cost through `Harness.account()`, which opens no span, and its tools run inside the `claude` binary
- Symptom: with `SCIO_OTEL_EXPORTER=otlp`, a trace viewer shows the tool-less roles (router, planners, advisor, gates, reviewer) but no coder, debugger, documenter or explorer turn and no `execute_tool` span when `SCIO_WORKER_BACKEND=claude_code`. Those turns are in the cost ledger only.
- Root cause: ADR 0012 added the worker seam with accounting and no tracing; `Harness._call` is where spans open, and the backend never goes through it.
- Fix: issue #102. `telemetry.account_span` records one finished turn made outside `_call`. It starts an `invoke_agent <role>` span `latency_ms` before now (OTel `start_time`, in ns) and ends it now. It sets the attributes an API turn's span carries (operation, agent name, provider, request and response model, response id from the request id, the `scio.tag.*` tags and `scio.thread_id`, the token and cache counts, `scio.usd`, `scio.attempts` = 1); only the finish reason is left out, which such a turn does not report. `Harness.account()` calls it after the ledger and the budget are recorded; its signature and return value are unchanged. A failure inside the helper is logged and never raised, so tracing cannot lose a ledger record or fail a turn. The request and usage attributes are one helper each (`_set_agent_attributes`, `_set_usage_attributes`), shared with `invoke_agent_span` and `record_response`, so the two paths cannot drift. The tools still run inside the `claude` binary, so there are still no `execute_tool` spans for them; `docs/OBSERVABILITY.md` says so.
- Sweep: the other paths that charge cost without `_call`: `grep -rn "\.account(" scio` finds the Claude Code worker only (`scio/loop/claude_code_worker.py`, `_account`, which serves the worker turn and its resumed summary call). `grep -rn "ledger.record(" scio` finds `Harness._call` and `Harness.account` only. `grep -rn "start_as_current_span\|start_span(" scio` finds the three span helpers in `telemetry.py` and no other.
- Guard: `test_an_accounted_turn_emits_an_invoke_agent_span`, `test_an_accounted_span_starts_latency_ms_before_it_ends` and `test_a_tracing_failure_never_fails_the_accounted_turn` (`tests/unit/test_account_spans.py`). Guardrail 124.
