### I-155 · The docs check read the parallel agents' checkouts and their installed packages
- Found: 2026-11-04 · issue #77, the local CI-equivalent on `fix/77-product-md-cap` while three worktree agents ran · `uv run python -m pytest -n 8`
- Symptom: `FAILED tests/unit/test_check_docs.py::test_repo_docs_pass`; `scripts/check_docs.py` printed `.claude\worktrees\agent-...\.venv\Lib\site-packages\openai\lib\responses_websocket\README.md: broken link -> ../../../../examples/responses/websocket.py` and the same for pdoc's templates README, 4 problems (514 other tests passed)
- Root cause: the agent tool puts each isolated agent's git worktree under `.claude/worktrees/` inside the repository, a whole checkout with its own `.venv`. `check_links` walks `ROOT.rglob("*.md")`, and `_skip` matched `.venv` and the caches only as top-level prefixes, so a nested `.venv` was read as this repository's docs. The worktrees were not git-ignored either, so `git status` listed them and ruff would have linted them (kept out here by a local `.git/info/exclude` line).
- Fix: `_skip` drops any path with a `NEVER_OURS` directory (`.venv`, `node_modules`, `__pycache__`, the caches) at any depth, and `.claude/worktrees` is in `SKIP_DIRS`; `.gitignore` ignores `.claude/worktrees/`
- Sweep: every whole-tree walk in the code directories and scripts (`grep -rn "rglob(\|os.walk(\|\.glob(\"\*\*" scripts scio evals`): `check_links` was the only one from the repository root; the other `rglob`s in `check_docs.py` start inside `scio`, `evals`, `tests`, `scripts`. `scio/aci/tools.py:104` (`repo_search`'s fallback when ripgrep is absent) walks a product tree, not this repository, skipping only `.git`; ripgrep, the normal path, honours `.gitignore`. Left as it is, outside this fix. pytest collects `testpaths = ["tests"]` only; mypy checks `packages = ["scio", "evals"]` only.
- Guard: `test_the_link_check_never_reads_another_checkout_or_an_installed_package`; guardrail 47
