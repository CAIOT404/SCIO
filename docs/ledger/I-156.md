### I-156 · A fresh agent worktree's first `uv run` built an environment without the extras, so mypy failed on code nobody changed
- Found: 2026-11-04 · issue #79, all three worktree agents of the S7 to S9 wave · `uv run python -m mypy` in `.claude/worktrees/agent-*`
- Symptom: "Found 19 errors in 5 files" (one agent; 20 for another), all `import-not-found` for fastapi, uvicorn, e2b, psycopg and the OTLP exporter, none in the agents' files
- Root cause: a new worktree has no `.venv`; the first `uv run` syncs the default groups only, and the type check imports the optional extras, which CI installs with `uv sync --all-extras`. The main checkout's venv had them from an earlier sync. One agent also found its worktree hook refusing a chained `cd <worktree> && ... && git status`; `git -C <worktree>` works (as I-144).
- Fix: each agent ran `UV_SYSTEM_CERTS=1 uv sync --frozen --all-extras --group dev` (CI's sync; `uv.lock` untouched), after which mypy passed. Future worktree briefs carry that line before the first check.
- Sweep: the environment lines in CLAUDE.md, CONTRIBUTING and the agent briefs of this session: none named the sync for a fresh checkout; CI's workflow does (`--all-extras`).
