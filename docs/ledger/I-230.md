### I-230 · A feature the owner skipped stops the build again at the milestone gate
- Found: 2026-11-15 · graphcalc M4 (issue #140) · graphcalc M4 gate, scio/product/build.py milestone_gate
- Symptom: the owner answered `skip` for P29 (thread `build-graphcalc-m4-p29-a1`, halted `escalate_human`). P30 passed and the integration checks were green (lint clean, 231 tests passed, acceptance passed). Then the build paused at `gate_decision`: "Milestone gate verdict escalate_human: The milestone is not fully delivered. P27, P28 and P30 are done, but P29 was skipped and needs a human decision", with P29's two criteria as `unmet_acceptance`. The skip's own question had promised "this milestone goes on without it".
- Root cause: `milestone_gate` put every feature whose latest run was not `passed` in `failed`, so a run the owner skipped (`status skipped`, `decision skip`) forced a `pass` verdict to `escalate_human`. The gate's input listed P29 with its criteria like any built feature, and prompt v1 told the model that pass means "every feature passed" and that a human skip is grounds for `escalate_human`, so the model's own verdict counted it as undelivered too. I-116 made a skip defer the feature in `next_feature`, `update_progress` and the PR body's `Refs #N`, but the gate was not revisited.
- Fix: `_deferred_by_owner` in `scio/product/build.py`: a feature whose latest run is `skipped` with `decision == "skip"` in this milestone is deferred. `milestone_gate` leaves it out of `failed` and out of the judged features, and lists it under "Deferred by the owner (not judged in this milestone)" with no criteria. A milestone whose every feature is deferred still has a pass overridden ("nothing was delivered"). Prompt `milestone_gate/v2.md` says a deferred feature is not judged and drops the skip as grounds for `escalate_human`. A failed run, a run nobody answered, a skip without the owner's `skip` and a skip from another milestone still stop the gate. ADR 0011 item 6 amended. Issue #140.
- Sweep: `grep -rn 'status != "passed"\|status == "passed"\|status == "skipped"\|"skipped"' scio/`. Hits: `build.py` `render_milestone_pr_body` (a non-passed issue is `Refs #N ... deferred, not closed`, already right for a skip), the recovered-runs scan (`status == "passed"` checks a commit is on the branch, not delivery), the planner's deferred note and `update_progress` (a skip stays open, I-116, unchanged), `ProductBuildState.next_feature` and `finished` in `scio/state/models.py` (a skip in this milestone finishes the feature, consistent), and the toolchain's check outcome (unrelated). Only `milestone_gate` counted a skip as undelivered.
- Guard: `tests/unit/test_skip_defers_at_gate.py`: `test_a_skipped_feature_does_not_stop_the_milestone_gate`, `test_the_gate_input_names_a_skipped_feature_as_deferred`, `test_a_failed_or_unrun_feature_still_stops_the_gate` (each failed on the old code) and `test_a_milestone_whose_every_feature_was_skipped_still_stops`. Guardrail 103.
