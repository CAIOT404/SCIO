### I-234 · Agents' own test runs miss the tests that scan the whole codebase; the gate caught two
- Found: 2026-11-15 · issue #141 · #140 and the #141 dashboard agents, their briefs' checks
- Symptom: twice in one day, a test failed only in the orchestrator's gate, after an agent reported green. The #140 agent's change broke `tests/graph/test_parallel_features.py::test_one_feature_halts_while_the_other_passes_and_a_resume_never_reruns_it`, which pinned the old second gate stop. The #141 dashboard agent wrote `subprocess.run(..., timeout=30)`, and `tests/unit/test_proctree.py::test_no_subprocess_timeout_outside_run_tree` (guardrail 74) caught it. Each cost a re-gate, about 10 minutes. Nothing was pushed either time.
- Root cause: to keep the machine's load down, each agent brief runs only the agent's own test files, at most `-n 4`. A test that scans the whole codebase for a forbidden construct lives in a file no agent owns, so no agent's checks ran it, and a change anywhere can break it.
- Fix: a pytest marker `scan` ("scans the whole codebase for a forbidden construct"), registered in `pyproject.toml`. It marks the 11 codebase scans: `test_proctree`, `test_lf_writes`, `test_dashboard_contract`, `test_dashboard_recovery`, `test_budget_guards` and `recovery/test_boundary` (one each), `test_ci_config` and `test_toolchain` (two each), and the new guard. `.claude/templates/agent-brief.md`'s checks run `uv run python -m pytest -q -n 4 -m scan` after the agent's own files. The 11 run in about 8 s.
- Sweep: `grep -rn -E "rglob\(|os\.walk\(|glob\.glob|\.glob\(" tests/`, then each hit read. The scans are the nine the detector found plus `test_budget_guards` (a module-level `.glob` over `scio/graph/nodes` and `scio/product`, marked by hand). The hits in `test_fragments`, `test_push_gate`, `test_runtime`, `test_worktree_guard`, `recovery/test_evidence` and `graph/test_product_build_fake` glob a `tmp_path` or fixture repository, so they are not scans. The #140 test pins behaviour across modules and does not scan, so `-m scan` does not cover that kind of slip.
- Guard: `tests/unit/test_scan_marker.py`. `test_the_agent_brief_runs_the_codebase_scans` reads the template's checks block. `test_every_codebase_scan_carries_the_scan_marker` parses every test module with `ast` and fails on any test that calls `rglob` or `os.walk` on a path built from the repository root without `@pytest.mark.scan`, whether it calls them directly, through a helper in the same module, or through a module-level name. Guardrail 106.
