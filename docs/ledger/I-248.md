### I-248 · A feature whose own tests skipped passed its verify, and the milestone gate passed with tests skipped
- Found: 2026-11-18 · issue #169 part B · scio/graph/nodes/verify.py _run_selectors; scio/product/build.py milestone_gate
- Symptom: graphcalc P33's browser tests (`tests/test_p33_wrapping.py`, behind `pytest.importorskip("playwright.sync_api")`) skip wherever Playwright is absent, and the feature, the integration and the Opus gate all passed with its rendered criteria never checked (issue #169). After part A (I-242) the skips are named, `skipped (not verified): path: reason` from `run_tests` and a `[test skips]` integration line, but nothing acted on them: verify still read a partly skipped run of a feature's own tests as proof, and the gate's `pass` stood.
- Root cause: verify's rule for a feature's own tests stopped at the all-skipped case (I-097): `_run_selectors` read any run that starts `all tests passed` as ok, so a run where some of the feature's tests skipped was proof. The milestone gate's code override read only `integration_ok`, the feature runs and the deferred set; `integration_checks` keeps the `[test skips]` line out of `ok` by design (part A), and no code read it as unmet.
- Fix (part B of #169): `_run_selectors` marks a selector run not ok when it passed with a `skipped (not verified)` line, and appends `UNVERIFIED_SKIP_HINT` (make the skipped test run: import what it needs plainly, put a missing package in the product's dependencies from the approved list for the install phase to install, or remove the skip; the hint does not name `install_deps`, which a Claude Code worker's turn does not have, `scio/loop/claude_code_worker.py:112`); the run's chunk keeps the skip line, so the feature's `test_output` and error text name the skip and its reason. `verify`'s I-037 fallback to the worker-reported tests also covers that case (`SKIPS_NOTE` in `unproven`). The whole-suite `_run` is unchanged. `milestone_gate` finds the `[test skips]` line in `state.integration`, appends it to `unmet_acceptance` (whatever the verdict) and overrides a `pass` to `escalate_human` with `tests skipped outside <acceptance dir>: <the line>`; a human may still `proceed`. The overridden reasoning is cut to `GATE_REASONING_MAX` (2000, `GateOutput.reasoning`'s limit), since the reason can now run to 600 characters in front of the model's own. `integration_checks`, `_check_verdict`, `integration_ok`, `run_tests`' strings and the profiles are unchanged.
- Sweep: `grep -rn "all tests passed\|SKIPS_NOTE\|SKIPPED_ONLY" scio evals --include=*.py`: verify's `_run_selectors` (fixed), `_run` (the regression check, unchanged by design) and `evals/solvers.py:222` (the eval grader of a hidden test file, which reads `all tests passed`; hidden tests do not skip, and an all-skipped run already fails there; left, not this change's file). `grep -rn 'verdict == "pass"' scio --include=*.py`: the task graph's `checkpoint_gate` overrides a `pass` when a feature is not passing, which now covers a task's skipped test through verify; the milestone gate is fixed. `release_check` runs the same integration checks on `main` before the human release stop and is unchanged.
- Guard: `test_a_feature_whose_own_test_skipped_fails_verify`, `test_the_failed_verify_names_the_skip_and_its_reason`, `test_the_milestone_gate_does_not_pass_with_skipped_tests`, `test_a_skip_outside_the_features_own_tests_does_not_fail_its_verify`, `test_an_acceptance_skip_fails_neither_verify_nor_the_gate`, `test_a_plan_filter_that_skipped_falls_back_to_the_workers_tests` and `test_the_skip_is_unmet_whatever_the_verdict_and_the_reason_still_fits` (`tests/unit/test_skipped_feature_tests.py`).
