### I-150 · A `"` in an issue title broke `find_issue`'s search phrase, so a resumed build opened a second issue
- Found: 2026-11-04 · issue #79, the graphcalc live run's S7 · `GitHubClient.find_issue` in the `issues` node of `build-graphcalc-m2`
- Symptom: P5's issue was created a second time (#12 at 18:50:59Z beside #8 at 18:39:43Z, the same title). Live (read-only), the search gets 0 hits for every graphcalc title that holds a `"` (#3, #4, #5, #7, #8, #12, #14), and the REST listing finds each one.
- Root cause: `find_issue` put free text into a search phrase, `in:title "{title}"`. P5's title holds `{"real","imag"}`, the first inner `"` ends the phrase, nothing matches, and `ensure_issue` creates. The search index also lags a create by seconds and stopped at `--limit 200`. `FakeGh` hid it: its `split('"')[1]` needle still matched (guardrail 18).
- Fix: `find_issue` lists `gh api --paginate "repos/{repo}/issues?state=all&per_page=100"`, skips rows with a `pull_request` key, matches `title` exactly, takes the lowest number of several and `url` from `html_url`. New `find_milestone_by_prefix` (I-149). `FakeGh` refuses what GitHub refuses: an inner `"` in a search phrase finds nothing, `--limit` caps, `search_lag`, a REST listing with PRs, `state` and pages. Checked live with gh 2.103.3: the listing finds all 12 graphcalc issues, None for PR #13's title; `find_milestone_by_prefix("M2: ")` gives `(2, "M2: Calculator errors, history, variables and UI")`. Note: for P5's title it now returns #8, the open orphan; effect `issue:M2:P5` is recorded, so nothing re-probes it.
- Sweep: `grep -rnE -- '--search|in:title|search/issues|q=|in:body|is:issue|is:pr'` over the repository: only `client.py` and the fake. `grep -rnE '\["gh"|"gh",|gh api|gh issue|gh pr '`: `scio/product/graph.py:341` (`gh repo create`) and `scripts/hooks/push_gate.py:176` (`gh run list --branch`) pass argv items, no phrase. Callers of `find_issue`/`ensure_issue`: the `issues` node only; task mode has none.
