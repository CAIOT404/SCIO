### I-241 · mypy passed on Windows and failed on CI's Linux: a sys.platform early return made the rest unreachable
- Found: 2026-11-17 · Workflow v3, WP1 (#158) · PR #160, `recovery/runner.py` `set_execution_state`; CI's tests (shard 1)
- Symptom: CI failed with `recovery/runner.py:90: error: Statement is unreachable  [unreachable]`. The local gate's mypy passed, and `land.py` refused to enqueue the PR, so nothing merged.
- Root cause: `if sys.platform != "win32": return` followed by Windows-only code. mypy evaluates `sys.platform` for the platform it runs on: on Linux the rest of the function is unreachable, and `warn_unreachable` reports it. The gate runs mypy only on this machine's platform (Windows), so it cannot see what CI's Linux run sees.
- Fix: the Windows code moved into an `if sys.platform == "win32":` block, the form `recovery/procs.py` already uses, which mypy skips on other platforms without a report. `uv run python -m mypy --platform linux` and the default run both pass.
- Sweep: `grep -n "sys\.platform" recovery/*.py scio/**/*.py scripts/*.py`: every other check is the block form. `uv run python -m mypy --platform linux` on the whole tree: no issues in 155 files.
- Guard: TODO: a `mypy --platform linux` step in `scripts/gate.py`, in its own PR (a gate change needs a `--full` gate).
