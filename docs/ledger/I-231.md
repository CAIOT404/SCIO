### I-231 · Every push-gate refusal in a SCIO session is logged twice
- Found: 2026-11-15 · #141 metrics · hook-refusals.log; scripts/hooks/push_gate.py registered at user and project level
- Symptom: building `scripts/metrics.py`, the machine's `hook-refusals.log` held 9 lines and only 6 distinct ones: each `double-backslash` or `backslash` refusal made in a SCIO session at 03:31:55Z, 04:00:57Z, 04:02:19Z and 04:11:49Z appears twice, with the same time, rule, command and directory. A refusal made in the graphcalc-run session appears once. Counted raw, the refusals per rule (W-18, the retrospective's count) come out doubled for SCIO sessions.
- Root cause: two `PreToolUse` hooks on `Bash` run `push_gate.py` in a SCIO session: the user-level one in `~/.claude/settings.json` (live-wt's copy, so every workspace is guarded) and the project-level one in `.claude/settings.json`. Each judges the command and each calls `log_refusal`, so one refusal is two lines. Nothing marks which registration wrote a line.
- Fix: the counting side. `scripts/metrics.py` counts an exact repeat (the same `at`, `rule`, `command` and `cwd`) once and reports how many it dropped (`duplicates_dropped`); two lines of one refusal that straddle a second boundary still count twice. Open: the logging side, one line per refusal, is the orchestrator's (`scripts/hooks/push_gate.py` or the user-level hook command; for example the user-level hook skips when `CLAUDE_PROJECT_DIR` is a SCIO checkout, since the project's own hook runs there).
- Sweep: every writer of a machine log: `push_gate.log_refusal` (two registrations on `Bash`), `worktree_guard.py` through the same `log_refusal` (one registration, project level, on `Edit|Write|NotebookEdit`), `scripts/gate.py`'s `gate-runs.log` and `scripts/slip.py`'s `slips.log` (one writer each, run by hand or by the gate). Only the push gate's lines repeat. Pattern: `log_refusal\|gate-runs.log\|slips.log` over `scripts/`, and the `hooks` blocks of both settings files.
- Guard: `test_a_slip_is_counted_in_the_machine_log_not_the_repo` (`tests/unit/test_metrics.py`) writes a refusal twice and expects it counted once, with `duplicates_dropped` 1.
