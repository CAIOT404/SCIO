### I-123 · `telemetry.SCIO_THREAD_ID` is defined but never set
- Found: 2026-10-27 · issue #68, wave 1 (agent D) · `scio/harness/telemetry.py` defines the attribute name `scio.thread_id`; no span sets it
- Symptom: a trace viewer can group spans by thread only through the tag attribute `scio.tag.thread`
- Root cause: the constant was declared for a planned attribute that no call site adopted
- Fix: issue #102. Every `invoke_agent` span sets `scio.thread_id` from the call's `thread` tag when the tag is present, beside `scio.tag.thread`: through the harness (`invoke_agent_span`) and for a turn accounted outside it (`account_span`, I-122), both through the one helper `_set_agent_attributes`. A call with no `thread` tag sets neither. `docs/OBSERVABILITY.md` names the attribute.
- Sweep: the other attribute constants in `telemetry.py` against their uses (`grep -oE "^[A-Z_]+ = \"(gen_ai|scio)\.[a-z_.]+\"" scio/harness/telemetry.py`, then each name across `scio`): every one is now set somewhere. The tag key the nodes use for the thread (`grep -rn "\"thread\":" scio`): `thread` in every node that tags its calls, so one key covers them all.
- Guard: `test_invoke_agent_spans_carry_the_thread_id` (both paths), `test_a_call_without_a_thread_tag_sets_no_thread_id`, and `test_every_telemetry_attribute_constant_is_set_by_a_span_helper`, which parses `telemetry.py` and fails on an attribute constant no function uses (`tests/unit/test_account_spans.py`).
