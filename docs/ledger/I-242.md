### I-242 · A UI feature passed every check with nothing rendering the page, and the product's CI skips its browser tests
- Found: 2026-11-17 · the graphcalc live run · graphcalc M7 merge stop, issue #169
- Symptom: graphcalc's graph tab drew `1/x` with a line across its asymptote (graphcalc#40), and every check SCIO ran had passed. The product's own CI read `360 passed, 5 skipped` against the local build's `365 passed, 4 skipped`, and nothing said which test had skipped.
- Root cause: three gaps, none of which failed anything.
  - P14's two acceptance criteria only check that ids and paths exist in the served files ("GET / contains elements with ids graph-f1, ..."). Its tests checked exactly that, so no test ever looked at the page. The milestone planner had no way to ask for more.
  - The python scaffold's CI install line is `pip install -e . ruff pytest`: no browser. The one module that drives the page starts with `pytest.importorskip("playwright.sync_api")`, so it skips in CI. Locally it runs only because the product venv sees SCIO's own Playwright through `scio_host_env.pth`.
  - The profile's pytest command is `-rfE`, which prints no skip reasons. `integration_checks` and `run_tests` read only the outcome, so a suite with a skipped feature test read `passed`.
- Fix (part A of #169; it turns no pass into a fail):
  - Planning: `MilestoneFeatureOutput.rendered_check` (default false), asked for by planner prompt v4 when a feature changes what a page shows and its criteria only check that elements, ids or strings exist. `normalise_milestone` carries it, and `feature_task` adds `RENDERED_CHECK_NOTE` to that feature's task: a browser test with `playwright.sync_api`, imported plainly, never through `importorskip`. A python product only: the note names Python's Playwright.
  - The product's CI: for a python product with `app.kind` http the scaffold writes `PYTHON_HTTP_INSTALL` (`pip install -e . ruff pytest playwright`) and a `BROWSER_INSTALL` step (`python -m playwright install --with-deps chromium`) in the CI and the README Develop block. `scio upgrade` rewrites the scaffold install line, old or current, and inserts the browser step once (`add_browser_install`). A cli product and node-ts are unchanged.
  - Skips: the profiles gain `test.skip_report_args` and `test.skip_line`; `Toolchain.test_argv(report_skips=True)` and `Toolchain.skips()` read them. `integration_checks` adds `[test skips] N outside tests/acceptance: path: reason; ...` (verdict `skipped`, `ok` unchanged), and a passing `run_tests` gains a second line `skipped (not verified): ...`. A skip under the acceptance directory is expected and never named. The default test command is byte for byte what it was.
  - Found while building: pytest keeps only the last `-r`, so `-rfE -rs` drops the `FAILED` lines. The profile's argument is `-rfEs`.
- Sweep: `grep -rn "test_argv(" scio`: nine call sites. `run_tests` and `integration_checks` now ask for the skip report. `run_acceptance` runs the acceptance directory, where the all-skipped case already fails (I-097). The bootstrap check (`scio/product/graph.py`) and the batch merge check (`scio/product/parallel.py`) read only pass or fail of a suite that integration runs again, and are left as they are. The scaffold and the worker's permission rule need the default command. `grep -rn "pip install" scio configs`: the scaffold's constants and `scio/product/spec.py` (a parsing regex). `grep -rn "importorskip" scio`: only the new note.
- Guard: `test_an_http_products_ci_installs_the_browser` and `test_upgrade_adds_the_browser_to_an_http_products_ci_once` (the CI has a browser), `test_integration_reports_skips_outside_acceptance_without_failing`, `test_an_acceptance_skip_is_not_reported` and `test_run_tests_names_a_skipped_feature_test` (a skip is named), `test_a_ui_feature_with_string_only_criteria_gets_a_rendered_check` and `test_a_stored_plan_without_rendered_check_still_loads` (the plan), `test_the_default_test_argv_is_unchanged`.
