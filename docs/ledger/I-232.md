### I-232 · The push-gate and worktree hooks never see the PowerShell tool
- Found: 2026-11-15 · issue #141 (the guardrail review) · .claude/settings.json PreToolUse matchers
- Symptom: the guardrail review asked whether each `hook:` guard refuses the act on every route. `.claude/settings.json` (and the owner's user-level `~/.claude/settings.json`) runs `push_gate.py` only for the matcher `Bash`, and `worktree_guard.py` only for `Edit|Write|NotebookEdit`. Claude Code sessions on this machine also have a PowerShell tool (the environment calls it the primary shell). A probe through the PowerShell tool, `Write-Output 'probe a\\b'`, printed its text: no hook refused the double backslash that the Bash hook refuses (guardrail 17). So a `git push` without a CI or gate reading, a bare `git stash`, an unlinted `git commit` and a backslash in a script all get through when they go through the PowerShell tool. Read from the matchers, not probed: a write to the main checkout from a worktree session through a shell (a PowerShell command or a Bash redirect) is not seen by `worktree_guard.py` either.
- Root cause: the hooks were written for the Bash tool and the file tools only; the PowerShell tool came later, and no matcher names it. `push_gate.py` also allows a command when it cannot check it (no `gh`, offline), by design.
