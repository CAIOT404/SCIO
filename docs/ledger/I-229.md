### I-229 · A parallel batch's worktree path is relative to the workspace, so git creates it inside the product tree and the feature's clone fails (#142)
- Found: 2026-11-15 · Product Mode, graphcalc M5 · scio/product/parallel.py worktrees_root/ensure_worktree, scio/graph/run_context.py RunContext.create; scio build, prepare_repo
- Symptom: the supervised run `run-20261115035400-837b67` (`scio build ... --decision merged`, recovery incident inc-20261115035430-4fad71) crashed 30 s in, at M5's first parallel batch (P29 attempt 2, P33 attempt 1): `RuntimeError: git clone failed: fatal: repository '.scio\worktrees\build-graphcalc-m4-p29-a2' does not exist` from `prepare_repo`. The product tree was left with `?? .scio/worktrees/`, and the effect log recorded `worktree:build-graphcalc-m4-p29-a2` done with the relative result `.scio\worktrees\build-graphcalc-m4-p29-a2`.
- Root cause: `scio build` passes no work directory, so `RunContext.create` used the relative `Path(".scio")`, and `worktrees_root` (`<artifacts>/../../worktrees`) was relative too. The batch hands that one path to two processes that resolve it against different directories. `git worktree add <path>` runs through `ctx.sandbox.exec`, whose working directory is the product tree, so git made the worktree at `graphcalc/.scio/worktrees/<thread>`, inside the product, which is what ADR 0018 and I-155 forbid. Python's own checks (`(path / ".git").exists()`, `path.parent.mkdir`) and the feature's `LocalSandbox(path)` resolve it against the process's working directory, the workspace `graphcalc-run`. The feature's sandbox was therefore an empty directory there, and `prepare_repo` found no `.git` and cloned `task.repo_url` (the same relative path) from inside that directory, which does not exist. Every parallel test passed an absolute `work_dir=tmp_path / ".scio"`, so the suite never ran the default relative one. The effect log made it sticky: a second `scio build` re-runs the batch with the same thread (no attempt was recorded), and `run_effect` returned the stored relative path without calling `apply`.
- Fix: `RunContext.create` resolves the work directory to an absolute path, and `worktrees_root` resolves its result as well. `ensure_worktree` always returns the path it computes, never the stored record. After `run_effect` it adds the worktree again when `.git` is missing there (a stale or relative record). It also fails at once when `git worktree add` succeeds but leaves no `.git` where Python looks. A new `drop_misplaced_worktrees`, run at the start of every batch, removes the worktrees the bug left registered under the product tree's `.scio/worktrees`, which `git clean -fd` keeps and a serial feature's `git add -A` would commit as embedded repositories. It keeps any under `worktrees_root`, as when a build runs from inside the product tree. Each removal is a ledger line. PR for #142.
- Sweep: the construct is a host path that may be relative, handed to a command whose working directory is the sandbox root and not the process's. `grep -rn "\.exec(" scio/` (69 calls in 17 files), reading each argv for a host path, and `grep -rn "str(path)\|repo_dir=\|cwd=" scio/`. Found and fixed: `ensure_worktree` and `remove_worktree` (`str(path)` to `git worktree add/remove`), and `feature_task(repo_dir=str(job.tree))` (the clone's URL in the feature's sandbox). All three take `worktrees_root`, which is absolute now. Checked and safe: `exclude_path` and `_git_path` join git's relative answer to `sb.root`; `LocalSandbox` and `DockerSandbox` resolve their roots; `claude_code_worker`'s `--system-prompt-file` is a `tempfile` path; `cli.py`'s `Path(".scio")` defaults (`--out`, the sandbox root, the cost ledger) are read in process or resolved by the sandbox; `GhRunner`, `apps.py` and `docker.py` pass no host path to another directory. `grep -rn "Path(\".scio\")\|artifacts.root\|work_dir" scio/` found no other work-directory path that leaves the process.
- Guard: `test:test_a_batch_from_a_relative_work_dir_builds_each_feature_in_its_own_worktree`, `test:test_a_worktree_recorded_at_a_relative_path_is_added_again_where_it_is_read`, `test:test_a_worktree_left_inside_the_product_tree_is_removed_before_the_batch`, `test:test_a_worktree_under_the_work_dir_inside_the_product_tree_is_kept`, all in `tests/graph/test_parallel_features.py`. The first two failed on the old code, the first with the incident's own error (`git clone failed: fatal: repository '.scio\worktrees\build-todo_cli-m1-p1-a1' does not exist`), the second with `WindowsPath('.scio/worktrees/build-todo_cli-m1-p1-a2')` not absolute.
