### I-233 · Under the merge queue, gh pr merge tried to enable auto-merge, which the repository refuses
- Found: 2026-11-15 · issue #141, the first landing under the merge queue · landing #143, `gh pr merge 143 --merge`
- Symptom: on `CAIOT404/SCIO`, whose ruleset requires a merge queue, `gh pr merge 143 --merge` on a green, CLEAN PR printed `! The merge strategy for main is set by the merge queue`, then failed: `GraphQL: Auto merge is not allowed for this repository (enablePullRequestAutoMerge)`. #143 stayed open and out of the queue. `scripts/land.py` (8871cd6) printed exactly that command as every merge line.
- Root cause: under a required merge queue, `gh pr merge` goes through `enablePullRequestAutoMerge`, and the repository's `allow_auto_merge` is false (`gh api repos/{owner}/{repo}` shows it; auto-merge is off by the owner's rule, I-227). The merge line came from the merge-queue research (`.scio/agents/122-merge-queue.md`). Its reading of the gh manual ("If required checks have passed, the pull request will be added to the merge queue") was never probed on this repository, where auto-merge is off.
- Fix: `land.py N --enqueue`. It re-checks the basis `land.py N` uses: the owner's approval, a fast revert, or low risk, never a high-risk PR without an approval. It requires CI green on the head (`watch_ci.py --sha`), then calls GraphQL's `enqueuePullRequest(input: {pullRequestId, expectedHeadOid})` and prints the queue position and state. The node id comes from `gh pr view --json id`. A PR already in the queue (`isInMergeQueue`) is left alone, with exit 0. Every merge line now reads `uv run python scripts/land.py N --enqueue  # adds it to the merge queue`, and nothing prints `gh pr merge`. The mutation's shape was checked by GraphQL introspection (`EnqueuePullRequestInput`: `pullRequestId: ID!`, `expectedHeadOid: GitObjectID`; `MergeQueueEntry`: `position`, `state`). The orchestrator's call on #143 returned `{"position":1,"state":"QUEUED"}`.
- Sweep: `grep -rn "gh pr merge\|pr merge "` over `*.py`, `*.md`, `*.json`, `*.toml` and `*.yml`, outside `docs/ledger/`:
  - `scripts/land.py` (the merge lines, the queue-exit message, the docstrings): all fixed.
  - `tests/unit/test_land.py`: now asserts the `--enqueue` line, and that `gh pr merge` never prints.
  - `recovery/repair.py` and ADR 0019: they deny `Bash(gh pr merge*)` to the repair session. The deny list is still right; whether it should also deny `land.py * --enqueue` is an open question for the owner.
  - `tests/recovery/test_brief.py`: an injection fixture, not a use.
- Guard: `test_enqueue_adds_an_approved_green_pr_to_the_queue` asserts the exact `enqueuePullRequest` call. `test_land_prints_the_merge_only_for_an_approved_pr` asserts that no merge line says `gh pr merge`. The tests' `_enqueue` helper fails on any `gh pr merge` call. Guardrail 104.
