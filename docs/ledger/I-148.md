### I-148 · A merge stop planned the next milestone from the old spec when PRODUCT.md no longer parsed
- Found: 2026-11-04 · issue #77, the graphcalc live run's S10 · reading `reread_product_md` before sending `merged`
- Symptom: `reread_product_md` (`scio/product/build.py:157-160`) catches the `ValueError` and returns `"PRODUCT.md unreadable now, the loaded spec stays"`, so `--decision merged` would plan M3 from the 22-feature spec with none of the fixes, and say so only in a ledger line
- Root cause: I-109 made every stop of a build thread re-read PRODUCT.md, but a parse failure fell back to the spec loaded at the thread's start, and nothing at the merge stop read the file before acting on `merged`. Behind it, `scio build` parsed the whole file just for its stack before the graph resumed (`scio/cli.py:144`), so an unparseable PRODUCT.md would have ended the command in a `ValidationError` traceback before any stop could refuse anything (found by the advisor's review before the fix was written).
- Fix: `product_md_problem` and `ProductMdUnreadable` in `scio/product/build.py`. The merge stop's question says up front that a merge answer will be refused while PRODUCT.md does not parse (the payload carries `product_md_error`). It refuses `merged` / `merge` then, pulls and merges nothing, asks again, and takes the same answer once the file parses. `reread_product_md` raises instead of keeping the old spec. `plan_milestone` halts `load_failed` with the parser's reason ("nothing was planned"), and `update_progress` records the merge, then halts instead of routing to the next plan or the release gate. `scio build` reads only the stack line (`declared_stack`).
- Sweep: `grep -rn "parse_product_md(" scio evals`: `scio/cli.py` (fixed: `declared_stack`); `load` (already halts `load_failed`); `reread_product_md` (fixed); `scio new --spec` (`scio/product/graph.py:441`, input checked before any thread exists); `scio upgrade` (`scio/product/upgrade.py:103` ended in a traceback: now `UpgradeRefused`, "PRODUCT.md does not parse; fix it first"); `evals/product_solver.py:80` (an eval task's fixed spec). `grep -rn "except ValueError" scio/product scio/cli.py`: no other parse failure falls back to an old value.
